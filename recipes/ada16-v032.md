# v0.32 / 16 GB Ada measured configurations

The [Ada benchmark dossiers](../docs/campaigns/ada16-v032.md) evaluate the 25–26 October 2026 campaigns on an RTX 2000 Ada Generation (16 GB, SM89, 70 W). See [local setup and reproduction](../docs/install.md) for environment and containment prerequisites.

## Qwen3.8-27B qualification settings

The `16-A-NVFP4` configuration uses the prepared `Qwen3.8-27B-W4A16-AutoRound-fast` target, integrated MTP-3, FlashInfer NVFP4 KV, embedding UVA offload, one active sequence, `GPU_UTIL=0.93`, prefix caching OFF, prefill budget 2048, and CUDA graph capture size 4. The auto-fit admission limit is **41,216 tokens** (42,246-token KV pool), recording **33.92 tok/s greedy / 30.57 instruct** output throughput and **193/200 GSM8K**; rungs above 41,216 are skipped.

## Gemma-4 12B settings and limits

Evaluates the `gemma-4-12B-it-QUASAR-W4A16-G64` target with NVFP4 KV, both target-only and with the external BF16 producer assistant (`gemma4_mtp`, $k \in \{1, 2, 3\}$) using model-appropriate `vllm serve` arguments:
- **Capacity vs. near-limit retrieval:** Engine admission reaches the native 262,144-token ceiling (1,034,045 target-only pool tokens), and the target-only ladder verifies **130,796 occupied tokens**, but **261K retrieval fails** in both the $k=3$ extended run and the target-only control.
- **Prefix parity & loader boundaries:** The $k=3$ 32K prefix-cache check fails cold/warm text parity, FP8 KV prefill cannot compile for head-dim 512 on SM89, and the int4 compressed-tensors assistant is boot-blocked by a missing `post_projection` mapping.
