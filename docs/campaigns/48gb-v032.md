# 48 GB Blackwell: benchmark dossiers

Scope: Qwen3.8-27B, Qwen3.6-35B-A3B and Gemma-4-31B on the NVIDIA RTX PRO 5000 Blackwell (48 GB, SM120, 300 W), using vLLM 0.32.0, FlashInfer 0.7.0.post1 and CUDA 13 with one active request. Measurements were collected on 28–29 October 2026.

PP is prompt-processing throughput. TG tables distinguish complete-request output throughput from decode rate. Admission, physical KV pool capacity and tested occupied context are separate measurements. Greedy TG retains the second pass unless stated otherwise. The standing GSM8K gate is 190/200 with the selected 200-question subset and a 768-token response limit; exceptions and filtered runs are identified below. ## Dossier 1: Native dense Qwen: weight preparation, KV precision and speculation

### Model and configuration

Target: Qwen3.8-27B, prepared AutoRound-fast W4A16 or Gittensor pre-final NVFP4. KV: BF16 or NVFP4. Speculation: target-only or external DFlash2-7. Prefix mode is stated per column.

### Evaluation conditions

Native selection used screening followed by full qualification for distinct serving roles. Host-memory containment: 48,000,000,000 bytes; swap disabled; control-group termination. One GPU, one active sequence.

Prefix-enabled DFlash2 has a separate failure boundary. W4A16/NVFP4-KV/DFlash2 scored 192/200 and 182.48 output tok/s but failed exact cold/warm prefix-output parity. Native NVFP4/NVFP4-KV/DFlash2 initially passed qualification parity, then failed parity in its extended repeat (192/200 GSM8K, 173.65 output tok/s), preventing the prefix-enabled variant from being treated as reproducibly passing.

## Dossier 2: Dense Qwen checkpoint comparison

### Model and configuration

Targets: Gittensor pre-final, QUASAR and kelnei preparations of Qwen3.8-27B. Native context, NVFP4 target/drafter KV, DFlash2-7 and prefix caching OFF.

### Evaluation conditions

Filtered comparison: selected TG, distribution and GSM checks; prefill only after a passing reasoning gate. This is not a full qualification. All TG rates retain pass 2.

### Results

| Prepared checkpoint | Retained greedy output tok/s | GSM8K |
| --- | ---: | ---: |
| Gittensor pre-final | 184.69 | 193/200 |
| QUASAR | 156.15 | 188/200 — standing gate failed |
| kelnei | 139.32 | 191/200 |

### Interpretation

These results support Gittensor's throughput advantage within the tested comparison. Differences of two or five correct answers on 200 questions do not establish a statistically significant reasoning ranking. The earlier corpus-PPL measurements were separate target-only runs, not rerun in this DFlash2 comparison. Kelnei's distribution check used an FP8 reference following an unresolved BF16-KV anomaly; this is not an estimate of absolute weight-quantization damage.

### Evidence

Selected values C053–C064. Earlier target-only PPL and this filtered DFlash2 comparison are distinct measurements. See the [evidence reference](evidence/48gb/README.md).

## Dossier 3: Dense Qwen extended context: YaRN-512K and YaRN-1M

### Model and configuration

Target: Gittensor pre-final Qwen3.8-27B, NVFP4 weights/KV, DFlash2-7. YaRN factors 2× and 4×; prefix OFF for separate near-max probes and ON for the 512K extended follow-up.

### Evaluation conditions

Smoke and near-max probes were separate runs. Near-max records contain boot plus the deep-context check. A separate prefix-ON 512K run executed the full extended battery.

### Results

| Engine limit | Actual prompt | Actual output | Actual occupied context | Streamed cold TTFT |
| ---: | ---: | ---: | ---: | ---: |
| 524,288 | 522,762 | 147 | 522,909 | 648.93 s |
| 1,048,576 | 1,047,050 | 182 | 1,047,232 | 2,515.29 s |

### Interpretation

Both near-max records report zero cached tokens and no missing expected strings. The repeated passcode does not independently establish retrieval at all three insertion depths. Outputs ended below the 512-token budget. At 1M the whole request lasted 2,517.08 seconds; this is separate from TTFT.

A separate 512K prefix-ON configuration completed the full extended battery with 190/200 GSM8K and 176.75 greedy output tok/s, but failed exact 32K cold/warm output parity. Its passing retrieval checks do not qualify prefix-output correctness. No full 1M extended qualification is claimed.

### Evidence

Selected values C028–C040, C065–C066 and C070–C072. Streamed TTFT and whole-request elapsed time use separate fields. See the [evidence reference](evidence/48gb/README.md).

## Dossier 4: Qwen MoE NVFP4-Fast: native extended evaluation

### Model and configuration

Target: Qwen3.6-35B-A3B-NVFP4-Fast, mixed FP8 attention/head and NVFP4 expert weights. Integrated MTP-3, NVFP4 KV, prefix ON, GPU vision.

### Evaluation conditions

Extended evaluation used 144 GiB host containment and a campaign-specific 180/200 GSM gate. The measured score also clears the standing 190/200 numerical gate. An FP8 reference selected for this campaign followed the unresolved BF16 discrepancy.

### Results

| Category | Metric | Result |
| --- | --- | --- |
| Capacity | Admitted tokens | 262,144 |
| Capacity | Physical KV pool token equivalents | 3,045,863 |
| Memory | Model / KV allocation | 22.05 / 20.16 GiB |
| Reasoning | GSM8K | 192/200; standing numerical gate passed |
| Language | Combined PPL | 7.5585 |
| Distribution | Mean top-20 KL vs approved FP8 reference | 0.040743; comparison passed |
| Distribution | Mean top-20 KL vs NVFP4 target-only | 0.037882; comparison passed |
| TG | Greedy output / decode | 336.49 / 342.47 tok/s |
| TG | Instruct output / decode | 313.92 / 319.49 tok/s |

| Occupied context | Near-max whole request | 80.52 s; 10,000 cached tokens |
| Prefix cache | Exact 32K cold/warm text parity | FAILED |

### Interpretation

The near-max request used 10,000 cached tokens (not a cold prefill) and generated 173 tokens. Passing the FP8 and NVFP4 target-only distribution comparisons does not resolve the BF16-reference discrepancy: the original BF16-reference gate failed, and the campaign continued against FP8 with that exception recorded. The reference investigation found FP8 versus BF16 mean KL of 0.271569 (57.29% top-1 agreement), while NVFP4 versus FP8 measured 0.038380 (87.84% agreement), making the BF16 path the outlier without establishing which path is ground truth. Because the 32K prefix check failed exact cold/warm text parity, the completed extended battery is not a clean qualification despite passing GSM8K (192/200) and near-limit retrieval.

## Dossier 5: Qwen MoE prefix caching: reproducibility controls

### Model and configuration

Targets: historical Qwen3.6-35B-A3B W4A16 and retained NVFP4-Fast preparations. The isolation matrix and cache-disabled controls are separate diagnostic experiments, not additional qualifications.

### Evaluation conditions

The controls compare cold/warm and warm/warm free generation, uncached repeated generation, and next-token predictions under a fixed continuation. These experiments assess attribution while keeping the original exact-parity criterion unchanged.

### Results

The first prefix tests established two observations: telemetry showed substantial reuse, yet identical greedy prompts could produce different cold and warm text. The follow-up question was whether reuse introduced the difference, or whether the same serving configuration already varied between uncached requests.

The historical W4A16 isolation matrix exercised nine arms spanning BF16/NVFP4 KV, speculation disabled or DFlash2, compiled/eager execution, and float16/float32 recurrent-state storage. Cold/warm or warm/warm text differences remained across those tested settings. None of these individual changes supplied a general exact-parity remedy. Cache-disabled repeat controls then showed variability without reuse, so a cold/warm mismatch alone could not identify caching as the cause.

Free generation can diverge after an early token change, making later tokens incomparable. Fixed-continuation probes instead held the continuation constant and compared the next-token choice. This asked a narrower question about local prediction variability, rather than comparing two already-diverged texts.

| Control | Free-generation observations | Fixed-continuation top-1 agreement |
| --- | --- | --- |
| W4A16, NVFP4 KV, DFlash2, cache OFF | Five distinct outputs among six requests | 16/18 first-to-repeat; 17/18 repeat-to-repeat |
| Same, cache ON | Five distinct outputs among six requests | 18/18 cold-to-warm; 18/18 warm-to-warm |
| NVFP4-Fast, MTP, cache OFF | Four distinct outputs among six requests | 16/18 first-to-repeat; 18/18 repeat-to-repeat |
| Same, cache ON | Five distinct outputs among six requests | 17/18 cold-to-warm; 16/18 warm-to-warm |

### Interpretation

The controls do not show a consistent worsening of next-token agreement with cache reuse in these probes. They also show that instability is not confined to the historical W4A16 preparation. The small sample does not quantify a general error rate or establish cache correctness.

The original exact-output criteria remain failed. The investigation establishes a narrower interpretation: baseline repeat variability confounds attribution to cache reuse. It does not establish factual corruption, exclude a cache defect, or isolate a numerical root cause. These controls were MoE tests; their explanation is not automatically transferred to dense DFlash2 or Gemma failures.

### Evidence

Diagnostic records DC001–DC067. Agreement counts are derived from fixed-continuation boolean outcomes; the original arrays remain private. See the [evidence reference](evidence/48gb/README.md).

## Dossier 6: Gemma-4-31B: numerical, chat and vision diagnostics

### Model and configuration

Target: Gemma-4-31B with NVFP4 weights. BF16/FP8/NVFP4 refer to KV precision. The assistant-depth-3 vision diagnostic uses FP8 KV and Triton; NVFP4 vision attempts use FlashInfer.

### Evaluation conditions

Quality stopping was disabled for the extended diagnostic so later measurements could be collected after a failed numerical gate. The separate chat comparison used target-only, prefix OFF, a 65,536-token limit and 15 cases per KV arm.

### Results

Gemma-4-31B with NVFP4 weights produced a conflict between useful chat behaviour and abnormal raw-text numerical measurements. Follow-ups examined input framing, backend/compilation choices, chat tasks and vision support separately. BF16 in these comparisons refers to KV precision, not an unquantized-weight reference.

Raw-text probes initially omitted Gemma's BOS framing. Correcting it improved the raw PPL measurements but did not produce a healthy numerical reference. Backend changes and eager execution also failed to resolve the recorded distribution discrepancies. The corrected and superseded records therefore answer different questions; the initial framing error cannot explain away every later failure.

| Evaluation | Measured result | Status / boundary |
| --- | --- | --- |
| FP8 KV, assistant k=3, GPU vision: GSM8K | 196/200; 0 truncations | Standing numerical reasoning gate passed |
| Same: greedy TG, retained pass 2 | 128.03 output tok/s | Diagnostic throughput |
| Same: mean top-20 KL | 0.215169 | Distribution gate failed |
| Same: cold/warm prefix text | Different | Exact parity failed |
| Target-only chat, BF16 / FP8 / NVFP4 KV | 8/13 / 9/13 / 8/13 strict answers | Hand-written diagnostic; 15 requests per arm, 0 truncations |
| NVFP4 KV with GPU vision | Initialization rejected | FlashInfer backend boundary; no served extended tests |

The FP8 assistant run completed the diagnostic extended battery despite its failed distribution and parity criteria. Its later results extend the measurement record without changing those failures.

A separate matched chat diagnostic submitted 15 cases per KV arm: BF16, FP8 and NVFP4. The strict mechanically scored subset yielded 8/13, 9/13 and 8/13 respectively, with zero truncated responses in each arm. The two remaining cases per arm were prose checks. The source report records coherent prose and successful retrieval on repetitive filler at roughly 60K tokens, alongside shared reasoning and formatting errors. NVFP4 used FlashInfer while BF16/FP8 used Triton, so the comparison does not isolate KV precision alone.

Finally, NVFP4 KV with GPU vision failed initialization on the tested FlashInfer path because partial multimodal-token full attention was unsupported. FP8 with the Triton path could execute the vision diagnostic. This is a backend/configuration boundary; it is separate from the unresolved text-quality measurements.

### Interpretation

Together the diagnostics establish that useful chat, a high reasoning-subset score, numerical distribution fidelity, exact output reproducibility and multimodal backend support can disagree in the same model preparation. No clean Gemma qualification is inferred, and without an unquantized-weight control the results do not establish damaged weights or a general intelligence ranking.

### Evidence

Diagnostic records DC088–DC108 and the diagnostic report source hashes. Qualitative chat, framing and backend findings retain report-level attribution. See the [evidence reference](evidence/48gb/README.md).
